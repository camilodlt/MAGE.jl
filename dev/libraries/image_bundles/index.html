See Image Lib for saliency, orientation and pooling galleries, and Core image operators: gallery for arithmetic, filtering, morphology, thresholding and segmentation effects. The Bundle Catalogue lists every registered operator by output type.

MAGE.image2D_filtering.bundle_image2DIntensity_filtering_factory — Constant
bundle_image2DIntensity_filtering_factory

Convolution filters on intensity images.

Gradients, in x, y and magnitude (m) variants: sobel, ando3, ando4, ando5, bickley, prewitt, scharr. Smoothing: gaussian5 through gaussian25, moffat5, moffat13, moffat25, and the difference of gaussians dog_image2D. Second order: laplacian3_image2D.

Every result is rescaled min to max into [0, 1] (a flat result is all 0). The derivatives *x / *y are signed: an edge getting brighter to the right (x) or downwards (y) comes out dark, the opposite edge bright, and flat areas in between. The gradients, Gaussians and Laplacian take an optional second input, the border mode: < 0 wraps around, 0 (default) repeats the edge pixels, > 0 mirrors.

This is a factory bundle: each entry is a function of a type that returns the method specialised for it, so the same operator can be instantiated for several image or element types. See Libraries for how factories are specialised into a library.

Orientation

MAGE.image2D_orientation — Module

Gradient orientation maps computed from Sobel derivatives.

Bundles

  • bundle_image2DIntensity_orientation_factory

The exhaustive, always-current list of operators in each bundle is on the Bundle Catalogue page.

Call tree

Every operator, e.g. orientation_select(img, θ, bw; out):

output_pixels(out, img)                       where to write: out.img or a new array
_sobel_gradients(img) -> (gx, gy)             Sobel derivatives in task scratch
├── pixel_values!(values, img.img)            pixels → Float64
└── _sobel_xy!(gx, gy, values)                (orientation_common.jl)
_magnitude! / _select_band!                   per-pixel values, written over gx
_store_rescaled! / _store_orientation!        min–max to [0, 1] / angle over π, cast
image_result(out, pixels, size_type)

All arithmetic is in Float64, as before (Float32 noise would defeat the _FLAT threshold that gives flat pixels orientation 0).

source
MAGE.image2D_orientation.bundle_image2DIntensity_orientation_factory — Constant
bundle_image2DIntensity_orientation_factory

Gradient orientation maps from Sobel derivatives:

  • grad_magnitude(img): edge strength, rescaled so the strongest edge of the image is 1.
  • grad_orientation(img): the gradient orientation (the direction across the edge) over π, in [0, 1): 0 for a vertical edge, 0.5 for a horizontal one. Angles run clockwise on screen. Flat pixels also read 0.
  • orientation_select(img, θ, bandwidth): the gradient magnitude, kept only where the gradient orientation is within bandwidth · 90° of θ · 180° (θ wraps around 1), then rescaled to [0, 1]. So θ = 0 keeps vertical edges and θ = 0.5 horizontal ones. Defaults θ = 0, bandwidth = 0.2 (±18°).

These use the gradient direction, perpendicular to the edge; the scalar summaries in bundle_float_orientation use the edge direction, so orientation_energy_90 measures the same vertical edges that orientation_select(img, 0) keeps.

For the scalar counterparts see bundle_float_orientation.

This is a factory bundle: each entry is a function of a type that returns the method specialised for it, so the same operator can be instantiated for several image or element types. See Libraries for how factories are specialised into a library.

Thresholding

MAGE.image2D_binarize — Module

Thresholding: intensity image in, mask out.

Bundles

  • bundle_image2DBinary_binarize_factory

The exhaustive, always-current list of operators in each bundle is on the Bundle Catalogue page.

How it is computed

The thresholds come from ImageBinarization (local methods: adaptive, Niblack, Sauvola, already O(1) per pixel through integral images; global methods: histogram thresholds) or from a manual threshold. Each call:

  1. copies the image's values once into a plain array (task scratch);
  2. runs ImageBinarization's in-place binarize! into a second scratch array (or, for the manual threshold, compares each value directly);
  3. writes the mask into the output pixels in one pass.

The values passed to ImageBinarization and the conversion of its result are those of the original implementation, so masks are unchanged.

Call tree:

binarize_<method>2D(img, params...; out)
├── _window_size / _percentage / _bias / _bins          evolved parameters → algorithm settings
├── _binarize_into!(pixels, image_pixels, algorithm, V; quiet, nbins)
│   ├── pixel_values!(values, image_pixels)              image_buffers.jl
│   ├── _is_constant(values)                             `Moments`, `Polysegment` only
│   ├── _run_binarize!(result, values, algorithm, quiet; nbins)
│   └── _store_mask!(pixels, result)
└── _threshold_into!(pixels, image_pixels, t)            binarize_manual2D

Pooling

MAGE.image_pool — Module

Block pooling: cut the image into a grid of k × k blocks, reduce each block to one value, and write that value back over the whole block. The output has the same size as the input (a blocky, "pixelated" version of it).

How it is computed

Blocks do not overlap, so every pixel is read once. For each block, the reducer (mean, maximum, minimum, or the mode for label maps) reads the block in place (the _cross_ variants first gather the block's centre row and column into a reused buffer), and the resulting pixel is written over the block. Nothing is allocated per block; the image's values and the buffer come from task scratch. Results are those of the original implementation.

Call tree:

<pool>(img, k; out)
└── _pool_blocks_into!(pixels, image_pixels, k, reducer, shape)
    ├── _block_size(k, image_pixels)
    ├── pixel_values!(values, image_pixels)                pooling_common.jl
    └── _pool_blocks!(pixels, values, k, reducer, shape, buffer)
        └── per block: _reduce_block(reducer, shape, block, buffer)
                       → _block_pixel(P, T, value), written with fill!

Bundles

  • bundle_image2DIntensity_pool_factory
  • bundle_image2DBinary_pool_factory
  • bundle_image2DSegment_pool_factory

The exhaustive, always-current list of operators in each bundle is on the Bundle Catalogue page.

bundle_image2DIntensity_pool_factory

Block pooling of intensity images: the image is cut into a grid of non-overlapping k × k blocks (from the top-left; the last row and column of blocks may be smaller), each block is reduced to one value, and the value is written back over the block. The output keeps the input's size and pixel type.

avgpool_blocks, maxpool_blocks, minpool_blocks reduce the whole block; the _cross_ variants reduce only the block's centre row and centre column (a "+" shape). Call op(img, k) (k rounded, clamped to 1 … the image side; default 2) or op(img).

MAGE.image_pooler — Module

Sliding-window pooling: reduce a window at every position, keeping the image's size.

Bundles

  • bundle_image2DIntensity_pooler_factory
  • bundle_image2DBinary_pooler_factory
  • bundle_image2DSegment_pooler_factory

The exhaustive, always-current list of operators in each bundle is on the Bundle Catalogue page.

How it is computed

Every pooler runs the same three steps (_pool_into!):

  1. the image's values are copied once into a plain array (task scratch);
  2. the statistic of every k × k window is computed into a small grid, with an algorithm that does not re-read the k² pixels of each window:
    • mean, std: summed-area tables of the raw integers (4 reads per window), with the original mean / std on the rare windows that sit on a rounding boundary, so results are identical to computing every window;
    • max, min: doubling spans on the raw integers (about 2·log₂k vectorised passes over the image);
    • median, interquartile range, unique count, argmax/argmin count, mode: a sliding histogram for 8-bit and binary images with windows of side 4 or more (the window moves by updating k leaving and k entering values), a reused sort buffer otherwise (small windows, N0f16, floats, labels);
  3. the grid is stretched back to the image size, rescaled for the count poolers, and written into the output pixels in one pass.

Nothing is allocated per window; working arrays come from task scratch.

Call tree:

<pooler>(img, k, stride; out)
└── _pool_into!(pixels, image_pixels, k, stride, statistic)
    ├── _window_and_stride(k, stride, image_pixels)
    ├── pixel_values!(values, image_pixels)                    pooling_common.jl
    ├── _pool_grid!(grid, values, windows, statistic, P)       one method per statistic family
    │   ├── mean, std:   _summed_area! (exact integers), _mean_grid! / _std_grid!
    │   │                (original mean/std on windows at a rounding boundary)
    │   ├── max, min:    _extreme_along_rows!, _extreme_along_columns! (doubling, raw integers)
    │   └── order stats: _order_grid!(…, _window_order_method(T, k))
    │       ├── SlidingHistogram: _histogram_grid! → _histogram_statistic
    │       │                   → _rank_value / _rank_pair → _rank_level
    │       │                   (IQR: _histogram_quantile → _quantile_of_ranks)
    │       └── SortedBuffer:     _buffer_grid!    → _buffer_statistic
    ├── _rescale01!(grid)                                      count poolers only
    └── _write_stretched!(pixels, grid)

MAGE.image_pooler.bundle_image2DIntensity_pooler_factory — Constant
bundle_image2DIntensity_pooler_factory

Sliding-window pooling of intensity images: meanpool, maxpool, minpool, stdpool, medianpool, uniquecountpool, argmaxcountpool, argmincountpool, iqrpool.

How it works, with op(img, k, stride) (defaults k = 2, stride = 1):

  1. a k × k window is placed at every stride-th position where it fits entirely inside the image (no padding), and reduced to one number;
  2. this smaller grid of results is stretched back to the image's size with nearest-neighbour sampling.

So the output keeps the input's size, but it is a slightly rescaled version of the window results: with k = 5 on 28 pixels there are 24 window positions per row, stretched over 28 pixels. With a larger stride the output looks blocky. k is clamped to 1 … the shorter side, stride to 1 … the longer side; NaN/Inf use the defaults.

The three count-based poolers (uniquecountpool, argmaxcountpool, argmincountpool) are min–max rescaled to [0, 1] over the image.

Compare bundle_image2DIntensity_pool_factory, which uses non-overlapping blocks.

This is a factory bundle: each entry is a function of a type that returns the method specialised for it, so the same operator can be instantiated for several image or element types. See Libraries for how factories are specialised into a library.
