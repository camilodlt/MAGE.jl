Automatically Defined Functions

An ADF is a subprogram promoted to a library operator. Once installed, every chromosome can call it as a single node, so a useful three-node idiom stops being something the search has to rediscover and becomes a primitive it can compose with.

How it works

The whole design turns on keeping function indices stable while their meaning changes:

  1. Reserve. extend_fn_lib_adf! appends a number of empty slots to a Library. An empty slot (EmptyADFDefinition) behaves as the identity on its first argument, so a genome may point at it from the very first generation without breaking.
  2. Fill. When a subprogram looks worth keeping, replace_adf_slot! installs it as an ActiveADFDefinition. Because the slot object (ADFSlotFunction) is mutable and stays in place, every genome already pointing at that index picks up the new behaviour without being rewritten.
  3. Track. The ADFRegistry knows every slot, which lets the search ask which ADFs a program uses (direct_adf_usage), what an ADF itself depends on (recursive_adf_dependencies), and whether a replacement is safe (can_replace_adf_slot).
  4. Flatten. flatten_adfs expands every ADF call back into ordinary CGP material, producing a genome that no longer needs the registry. This is what makes a final model portable and readable.

The definition of an active ADF is stored as a genome, not as compiled code: that is what allows step 4. A SequentialProgram is cached alongside it purely as a fast callable view.

Slots and definitions

MAGE.ADFSlotFunction — Type
ADFSlotFunction

Callable object stored inside a FunctionWrapper. Keeping the slot object stable lets genomes keep the same function index while the slot definition is replaced during search.

Example: function index 21 can keep pointing at the same slot after it changes from identity to adf_sum_div.

slot(inputs...)

Call an ADF slot as a normal function. This method is what the slot's FunctionWrapper invokes during program evaluation.

Example: slot(2, 3) executes the sequential program currently installed in slot.

source
MAGE.ActiveADFDefinition — Type
ActiveADFDefinition(genome, shared_inputs, model_architecture, meta_library, sequential_program)

Genome-backed definition used by an ADF slot after it has been replaced by a subprogram extracted from an elite.

The genome is the canonical representation because it can be flattened back into normal CGP material. The sequential program is a cached callable view used for fast ADF execution and for source rendering.

Example: an ADF storing add(x, y) can run as slot(2, 3) == 5.

Reserving slots in a library

ADFRegistry()

Registry of ADF slots available during one run. The registry is the object used to check replacement safety and recursive ADF dependencies.

Example: registry.slots[21] returns the mutable ADF slot registered at function index 21.

MAGE.extend_fn_lib_adf! — Method
extend_fn_lib_adf!(library, registry, output_type, how_many; ...)

Append reserved ADF function slots to one library. Empty slots behave as identity functions until replace_adf_slot! installs a real sequential program.

The slot wrapper is appended to library.library immediately so this works on already-unpacked libraries used during a running search. The bundle is also kept in library.bundles so the extension is visible in library metadata.

Example: extend_fn_lib_adf!(lib, registry, Float64, 10) appends ten Float64 ADF placeholders.

Extracting a step's dependency cone

Step harvesting can turn a compiled intermediate result into a reusable ADF. The current extraction helper supports Float64 cones with at most three formal inputs; it returns nothing for unsupported cones. Keep the original library's function indices when installing the extracted genome. Connection setters check bounds and ordering; callers remain responsible for compatible types.

MAGE.adf_genome_from_step — Method
adf_genome_from_step(prog::SequentialProgram, step_index::Int,
                     arch::modelArchitecture, ml::MetaLibrary; max_nodes::Int=8)

Copy a Float64 step's dependency cone into a UTGenome with exactly three Float64 formal inputs. Call adf_step_input_indices(prog, step_index) to obtain original input indices in formal-argument order; unused arguments are ignored. Return nothing if the cone exceeds three inputs or max_nodes nodes. Non-Float64 cones are currently unsupported (return nothing).

Install using SharedInput for three Float64 values and an architecture with three Float64 inputs (all pointing to the Float64 chromosome), the original chromosome types, and one Float64 output. The meta-library must be the original library, with identical function indices. No original genome material is edited.

ADFSlotFunction's which reports nargs = length(slot.input_types) + 2. The decoder subtracts two, so an arity-three CGP node passes exactly three arguments to a three-input installed ADF, despite its Julia varargs call method. Empty reserved slots declare one input until replacement.

active_adf_calls(genome, shared_inputs, model_architecture, meta_library)

Example: a genome whose active path calls adf_3 once returns that decoded call operation.

call_input_mapping(call_operation, call_program)

copied_adf_body(program)

MAGE.flatten_adfs — Method
flatten_adfs(genome, shared_inputs, model_architecture, meta_library, registry; max_depth)

Saving and loading

An ADF environment is a genome plus the definitions its slots hold, saved together so a run can be resumed or an individual shipped elsewhere.

MAGE.SavedADFDefinition — Type
SavedADFDefinition

One genome-backed ADF exactly as it existed when an individual was saved. The stored genome is the canonical representation; source is the readable sequential code attached for inspection and LLM-facing workflows.

Example: a saved adf_remove_holes definition stores its old slot id, genome, source, and ADF refs it calls.

source
MAGE.SavedADFEnvironment — Type
SavedADFEnvironment(environment_id, definitions)

The set of ADF definitions needed to interpret one saved individual without relying on the current mutable run registry. This is not a callable Julia closure; it is a namespaced ADF context captured at save time.

Example: if an individual calls adf_201, which calls adf_190, this environment stores both definitions.

source
MAGE.SavedADFRef — Type
SavedADFRef(environment_id, slot_id)

Identifies an ADF slot inside one saved ADF environment. The environment id is part of the identity because two historical individuals can both use old slot 189 while meaning different ADF definitions.

Example: SavedADFRef(:elite_1_gen_50, 189) is distinct from SavedADFRef(:elite_2_gen_90, 189).

source
MAGE.SavedIndividualWithADFEnvironment — Type
SavedIndividualWithADFEnvironment

A saved genome plus the ADF environment required to interpret its ADF function indices. The environment prevents old ADF slot numbers from colliding with ADFs saved from other individuals or later generations.

Example: two saved individuals can both contain function index 189 because each carries a different SavedADFEnvironment.

source
