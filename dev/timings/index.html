Timing methodology

Library gallery pages end with measurements generated by the same calls that produce their images and scalar results. Each distinct operator/input combination is warmed once, then measured up to three times. The gallery uses the first call's output; measurements never substitute a mock or a simplified kernel. Factories, loading fixtures, plotting and PNG encoding are outside the timer. Base.invokelatest is included because the image factories define methods at runtime. Program evaluation, casters, fallbacks and wrapper caches are separate costs; these tables measure successful operator calls.

The median and slowest observed sample are wall-clock times, including allocation and any garbage collection during the call. They are sensitive to CPU load. A slowest sample is not an upper bound on future calls or on other inputs. First-use compilation and scratch-buffer allocation can make the first call considerably slower than these warmed measurements. Allocations report bytes allocated, not peak memory or memory retained by scratch buffers.

For a local build with a busy computer:

MAGE_DOC_TIMING_SAMPLES=3 nice -n 15 julia --project=docs docs/make.jl

The docs environment must already have been instantiated with this checkout of MAGE developed into it. Keep Julia and BLAS thread counts low when sharing CPU resources. Set MAGE_DOC_TIMING_SAMPLES from 1 to 20 to change the sample count. Sampling stops after at least 0.1 seconds of measured work per case; this limits repeat work, and does not interrupt an individual operator.

Input dimensions and pixel storage are listed once in a legend on each page. For scalar plots, numeric calls of the same operator and arity are grouped: the argument ranges describe the sampled values, the median is the median of the individual case medians, and the maximum spans all observed samples. Image calls retain separate rows for each image and parameter combination. This keeps the full set of measurements readable without printing hundreds of nearly identical rows for every point in a curve.

Inputs that change the cost

FamilyCases to inspectWhy
Connected components and blob/shape operatorsempty, full, many isolated pixels, diagonal contacts, long thin objectsRun count, object count and bounding-box overlap change work and scratch memory. Foreground is usually 8-connected; a checkerboard alone is not a collection of isolated objects.
Per-object convex hullsinterleaved objects with overlapping large boxesEach object's bounding box is scanned; total box area can exceed image area substantially.
Skeletonslarge solid shapes, thick ringsThinning makes repeated passes; thick objects can need more iterations.
Distance mapsempty and full masks, sparse and dense objectsEmpty/full cases can take shortcuts. Normalisation and behaviour with no target pixels matter.
Filters and morphologymaximum window/radius, long narrow images, constant imagesKernel size, border work and repeated neighbourhood comparisons change cost. Normalising a flat response needs a defined output.
Template matchingtextured image, larger template, repeated patterns, flat templateCorrelation work depends on candidate count and template area. Flat templates exit early. Coarse-to-fine search can miss the global best match; neither broad nor repeated peaks guarantee an exact result.
Shift estimationlong row/column profiles and flat imagesProfile correlation compares many lags: quadratic in the profile length, in addition to reading pixels. Flat profiles contain no motion evidence and return zero through a linear-time shortcut.
Graph descriptorsmany components, nearly collinear centroidsGraph size, triangulation and centrality dominate; fewer than three non-collinear nodes give the documented fallback.
Graph cuts / GrabCutnoisy intensities, ambiguous seeds, maximum iterationsCut topology and iterative appearance fitting affect time; one smooth fixture does not bound it.
Volumeslarger cubes, thin slabs, dense foreground and cavitiesVoxel count grows cubically with side length. A 28³ phantom does not predict full-resolution CT cost.
Evolved numeric parametersNaN, infinities, large finite values, endpointsSanitisation often clamps parameters or selects defaults; those branches deserve both correctness tests and measurement.

Small stress gallery

The following bounded fixtures exercise shortcuts, fragmentation, thick shapes and unusual parameters. They deliberately stay small so building the manual on a loaded machine is practical. They are examples of expensive or degenerate cases, not an exhaustive search for the worst input.

g_gallery(page, entries; cols = 4, asset_prefix = g_asset_prefix(library_page = false))
emptyshape_fill_holes: emptyshape_convex_hull_objects: emptyshape_skeleton: empty
fullshape_fill_holes: fullshape_convex_hull_objects: fullshape_skeleton: full
isolatedshape_fill_holes: isolatedshape_convex_hull_objects: isolatedshape_skeleton: isolated

A full foreground has no background sample: shape_distance_inside returns ones by convention. An empty foreground returns zeros. The shape gallery and source docstrings describe the other output conventions.

Julia 1.13.2; znver3; 1 Julia thread(s); optimisation level 2.
