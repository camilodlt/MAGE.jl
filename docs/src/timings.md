# Timing methodology

Library gallery pages end with measurements generated by the same calls that
produce their images and scalar results. Each distinct operator/input combination
is warmed once, then measured up to three times. The gallery uses the first
call's output; measurements never substitute a mock or a simplified kernel.
Factories, loading fixtures, plotting and PNG encoding are outside the timer.
`Base.invokelatest` is included because the image factories define methods at
runtime. Program evaluation, casters, fallbacks and wrapper caches are separate
costs; these tables measure successful operator calls.

The median and slowest observed sample are **wall-clock times**, including
allocation and any garbage collection during the call. They are sensitive to
CPU load. A slowest sample is not an upper bound on future calls or on other
inputs. First-use compilation and scratch-buffer allocation can make the first
call considerably slower than these warmed measurements. Allocations report
bytes allocated, not peak memory or memory retained by scratch buffers.

For a local build with a busy computer:

```sh
MAGE_DOC_TIMING_SAMPLES=3 nice -n 15 julia --project=docs docs/make.jl
```

The docs environment must already have been instantiated with this checkout
of MAGE developed into it. Keep Julia and BLAS thread counts low when sharing
CPU resources. Set `MAGE_DOC_TIMING_SAMPLES` from 1 to 20 to change the sample
count. Sampling stops after at least 0.1 seconds of measured work per case;
this limits repeat work, and does not interrupt an individual operator.

Input dimensions and pixel storage are listed once in a legend on each page.
For scalar plots, numeric calls of the same operator and arity are grouped:
the argument ranges describe the sampled values, the median is the median of
the individual case medians, and the maximum spans all observed samples.
Image calls retain separate rows for each image and parameter combination.
This keeps the full set of measurements readable without printing hundreds
of nearly identical rows for every point in a curve.

## Inputs that change the cost

| Family | Cases to inspect | Why |
|:--|:--|:--|
| Connected components and blob/shape operators | empty, full, many isolated pixels, diagonal contacts, long thin objects | Run count, object count and bounding-box overlap change work and scratch memory. Foreground is usually 8-connected; a checkerboard alone is not a collection of isolated objects. |
| Per-object convex hulls | interleaved objects with overlapping large boxes | Each object's bounding box is scanned; total box area can exceed image area substantially. |
| Skeletons | large solid shapes, thick rings | Thinning makes repeated passes; thick objects can need more iterations. |
| Distance maps | empty and full masks, sparse and dense objects | Empty/full cases can take shortcuts. Normalisation and behaviour with no target pixels matter. |
| Filters and morphology | maximum window/radius, long narrow images, constant images | Kernel size, border work and repeated neighbourhood comparisons change cost. Normalising a flat response needs a defined output. |
| Template matching | textured image, larger template, repeated patterns, flat template | Correlation work depends on candidate count and template area. Flat templates exit early. Coarse-to-fine search can miss the global best match; neither broad nor repeated peaks guarantee an exact result. |
| Shift estimation | long row/column profiles and flat images | Profile correlation compares many lags: quadratic in the profile length, in addition to reading pixels. Flat profiles contain no motion evidence and return zero through a linear-time shortcut. |
| Graph descriptors | many components, nearly collinear centroids | Graph size, triangulation and centrality dominate; fewer than three non-collinear nodes give the documented fallback. |
| Graph cuts / GrabCut | noisy intensities, ambiguous seeds, maximum iterations | Cut topology and iterative appearance fitting affect time; one smooth fixture does not bound it. |
| Volumes | larger cubes, thin slabs, dense foreground and cavities | Voxel count grows cubically with side length. A 28³ phantom does not predict full-resolution CT cost. |
| Evolved numeric parameters | NaN, infinities, large finite values, endpoints | Sanitisation often clamps parameters or selects defaults; those branches deserve both correctness tests and measurement. |

## Small stress gallery

The following bounded fixtures exercise shortcuts, fragmentation, thick shapes
and unusual parameters. They deliberately stay small so building the manual on
a loaded machine is practical. They are examples of expensive or degenerate
cases, not an exhaustive search for the worst input.

```@setup stress
using MAGE
include(joinpath(dirname(pathof(MAGE)), "..", "docs", "gallery_helpers.jl"))
page = "timing_stress"
n = 48
fields = [
    "empty" => falses(n, n),
    "full" => trues(n, n),
    "isolated" => [r % 3 == 0 && c % 3 == 0 for r in 1:n, c in 1:n],
    "thick ring" => [8^2 <= (r - 24)^2 + (c - 24)^2 <= 20^2 for r in 1:n, c in 1:n],
]
B = typeof(g_binary(fields[1].second))
I = typeof(g_intensity(zeros(n, n)))
shape(name) = bundle_image2DBinary_maskshape_factory[name].fn(B)
entries = []
for (k, (label, values)) in enumerate(fields)
    mask = g_name!(g_binary(values), label)
    push!(entries, ("input_$k.png", label, mask))
    for name in (:shape_fill_holes, :shape_convex_hull_objects, :shape_skeleton)
        out = g_call(shape(name), mask)
        push!(entries, ("$(name)_$k.png", "`$name`: $label", out))
    end
end
flat = g_intensity(fill(0.4, n, n))
textured = g_intensity([mod(37r + 53c * r, 101) / 100 for r in 1:n, c in 1:n])
g_name!(flat, "flat")
g_name!(textured, "textured")
for image in (flat, textured), parameter in (NaN, Inf, -Inf, 1e30, 13.0)
    g_call(bundle_image2DIntensity_morph_factory[:erosion_2D].fn(I), image, parameter)
end
for image in (flat, textured)
    g_call(MAGE.number_similarityFromImg.sim_shift_x, image, image)
    g_call(MAGE.number_similarityFromImg.match_score_30p, image, image)
end
```

```@example stress
g_gallery(page, entries; cols = 4, asset_prefix = g_asset_prefix(library_page = false))
```

A full foreground has no background sample: `shape_distance_inside` returns
ones by convention. An empty foreground returns zeros. The shape gallery and
source docstrings describe the other output conventions.
